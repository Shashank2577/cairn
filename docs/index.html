WP 01 The problem

Every session starts back at the trailhead.

A coding agent arrives knowing nothing about your project. It is capable, and it spends the first stretch of every session rediscovering what the last session already knew. Then it leaves, and the next one starts over.

  1. It re-reads the same files

    To change one module it opens the module, its callers and their callers, every session, for every developer.

  2. It misses the caller three hops away

    A search finds the direct imports. The break shows up later, in a test nobody thought to run.

  3. It repeats the fix you reverted

    Why that change was rolled back lives in a commit message and a closed pull request. The agent reads neither.

  4. It never heard the decision

    The convention your team agreed on in review last month lives in someone's head and a chat thread.

  5. Every teammate's agent learns it again

    Five developers, five agents, five separate discoveries of the same gotcha. Switch from Claude Code to Codex and the count starts over.

  6. You pay for the rediscovery

    Reading whole files to find one answer is the most expensive context an agent can load, and it lands on every session's bill.

WP 03 What it remembers

Five layers, stacked from what your repository already holds.

Run one setup command and Cairn reads your code, git history, specs, ADRs and docs. From then on every commit, spec and agent session adds to it. The first four layers need no model at all.

The base never needs a model. The top stone changes every session.

Layer 1 · base

Map

What is the code, and what depends on what?

Tree-sitter parses your source into a graph of files, symbols, imports and calls, with 25 languages built in. Cairn finds the hubs everything flows through and the areas the code falls into, so an impact question can follow a change three hops out.

WP 04 Field guide

Every feature answers a question and prevents a mistake.

Agents reach these through MCP tools and hooks. People reach the same answers in the terminal and on the local page. Each answer is a short, cited pack that fits a token budget.

  1. 01

    Where did I leave off?

    Session-start brief in every wired agent · the visible panel in Claude Code

    Prevents redoing yesterday's work, or quietly undoing it.

  2. 02

    What breaks if I change this?

    cairn impact · cairn_impact

    Prevents breaking a caller three hops away and skipping the tests that cover it.

  3. 03

    Why is the code like this?

    cairn why · cairn_why

    Prevents re-introducing a fix that was reverted, or reversing a decision nobody wrote down in the code.

  4. 04

    Which files are fragile?

    Handle with care in the panel · risk level in every impact answer

    Prevents editing a file with a long run of fixes and reverts without knowing it.

  5. 05

    Does the code still match the spec?

    cairn drift · cairn_specs with drift

    Prevents code silently drifting away from what the spec promised.

  6. 06

    What does the team know about this?

    cairn recall · cairn_recall · cairn remember

    Prevents making the same correction to an agent in every session.

  7. 07

    Did an agent already solve this?

    cairn sessions search · cairn_session_search

    Prevents solving the same problem twice in two agents.

  8. 08

    What was true, and when?

    cairn timeline search --at · cairn_facts

    Prevents acting on a fact that stopped being true after a refactor.

  9. 09

    What does this prompt need?

    Ambient context on each Claude Code prompt · 500 tokens at most · code prompts only

    Prevents the agent skipping memory because it did not think to ask.

  10. 10

    What should the reviewer look at?

    cairn review-context --files

    Prevents approving a diff without seeing its callers, tests and history.

  11. 11

    What happened since yesterday?

    cairn standup

    Prevents a standup pieced together from memory and scrollback.

  12. 12

    Where is it, and how does it connect?

    cairn search · cairn trace path · cairn hubs

    Prevents opening whole files to find one symbol.

WP 05 The whole lifecycle

The memory under an AI-native development cycle.

People and agents trade work at every stage, from spec to ship. Cairn is what both sides read from and write to, so each stage starts with what the last one learned, and the next cycle starts ahead of this one.

  1. Specify person + agent

    /cairn.specify and /cairn.clarify write the spec. Answers that are lasting decisions are stored as memory.

  2. Plan agent

    /cairn.plan grounds the plan in context, impact and recall. /cairn.tasks checks impact for every file the tasks name.

  3. Implement agent

    The panel and brief at session start, context on each prompt, impact and why before edits. Hooks capture the session.

  4. Review person + agent

    cairn review-context for the changed files, and cairn drift until it is clean or every finding is explained.

  5. Ship person

    Git hooks re-sync after the merge. cairn standup reports commits against the requirements they touch.

  6. Learn agent + person

    Session summaries, timeline facts and one to three recorded learnings per implemented spec. The next cycle starts with them.

What becomes possible

  • Agents that check the history before repeating a reverted fix.
  • A new hire whose agent knows the team's conventions on the first day.
  • Reviews that see callers, tests and past reverts next to the diff.
  • Impact across repositories: name sibling repos in system.yaml and review packs include hits in them.
  • Knowledge that stays when people move on to other work.
  • Mixing and switching agents without losing what any of them learned.

WP 07 How it works

It runs on your laptop, next to your agents.

Hooks and an MCP server connect each agent to one local Cairn. Five engines write their results into a single SQLite read model inside the repository, and every surface reads from it: the CLI, the agents' tools and the local page. A team server and a model are optional.

  • Your code is the input

    Reading it where it already lives means no upload and no second copy of your source to secure.

  • Capture is the sensitive part

    File contents, command output and prompts are most of what Cairn records. They stay on the machine that produced them.

  • Useful on day one, offline

    Map, impact, why, drift, recall and the session panel run without a model, a server or an API key.

  • Deterministic first

    Answers are computed, cited and budgeted. A model narrates and summarises on top, and never decides what is true.

WP 08 Setup and commands

Install once. Then mostly forget the commands.

Agents call Cairn on their own. The commands are for you: to check what an agent will be told, to review, and to run the team's day. You need Python 3.11 to 3.13 and git. No Docker, database server or API key.

  1. Install the CLI

    One tool on your PATH. The Python pin matters: a dependency has no 3.14 wheels yet on macOS and Windows.

    1. uv tool install --python 3.12 cairn-brain

  2. Wire every agent

    Adds Cairn's tools, memory at session start and session capture to each agent's user-level config. In a repository without Cairn, your agent offers setup in one line and writes nothing until you say yes.

    1. cairn global install

  3. Set up a repository

    Builds the map, seeds memory and installs git hooks. About 15 seconds with no model. Worktrees share the main checkout's memory automatically.

    1. cairn init --no-deep

Where your data lives

  • On your machine. Capture, map, memory and ledger live in the repository's .cairn/ folder.
  • Private stays private. Anything inside <private> tags is never stored. Values that look like keys, passwords or bearer tokens are masked before they are written.
  • Out of git. Memory files written for Copilot, Antigravity and Windsurf are excluded locally, so they are never committed.
  • Local embeddings. Search vectors are computed on your machine. Offline, a built-in hashing embedder takes over.
  • Loopback only. The local server listens on 127.0.0.1. Anything wider requires team mode with sign-in.
  • Cairn does not watch itself. Its own model calls are never recorded as sessions.

What it costs to run

  • No model on day one. The map, impact, why, drift, recall and the session panel are computed from your repository with no model.
  • Your model, when you want one. Cairn uses an Anthropic or OpenAI-compatible key, a local endpoint, or your signed-in Claude Code plan, and gives each job to the cheapest tier that does it well.
  • Budgets you set. Timeline facts stop at 150,000 tokens per sync by default. Turn them off with [deep] enabled = false, or queue session notes for later with [recall] worker_spawn = false.
  • A ledger of every call. Task, tier, model and tokens, on your machine.

WP 10 Why a cairn

Every session leaves the route better marked.

A cairn is a pile of stones that walkers leave to mark a route for whoever comes next. Nobody builds one alone. Each person who passes adds a stone, and the path gets easier to follow.

Cairn is institutional memory for teams of people and agents. Every commit, spec, review and session adds a stone. Whoever comes next, a teammate, a new hire or an agent in a different tool, finds the way already marked.

WP 11 For partners and investors

Why now, and why this shape.

The case in three parts, for anyone deciding whether to build on Cairn, partner with us or back it.

  1. Why now

    Every team runs several agents, and memory is split by vendor.

    Developers mix Claude Code, Codex, Cursor, Copilot and others, often in the same week. Where an agent remembers anything, it remembers inside its own product. The team's knowledge ends up scattered by tool and by person.

  2. Why Cairn

    Agent-neutral, local-first, open, and the customer owns the data.

    One memory for seven agents. It runs on the developer's machine, under Apache-2.0, and keeps what it knows in the repository, the team's git and the team's own server. Nothing is locked in a vendor's cloud.

  3. The business

    Open source first, then Team, then Enterprise.

    Developers adopt the open-source release one repository at a time. Teams pay for the hosted view across repositories. Enterprises pay for self-hosting, SSO and SCIM, audit and data controls.
