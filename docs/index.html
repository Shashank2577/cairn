Memory for coding agents · open source

Your agents forget. Your team shouldn’t have to.

Cairn gives every coding agent your team uses the same memory: what the code does, why it is that way, what was already tried, and where the last session stopped. It runs on your machine, and your code stays there.

uv tool install --python 3.12 cairn-brain

Works with Claude Code, Codex, Cursor, Copilot CLI, Gemini CLI, OpenCode and Antigravity. Apache-2.0.

The problem

Every session starts from zero.

A new agent session doesn’t know what the last one learned, what your teammate’s agent found yesterday, or which fix was already reverted twice. It rereads the same files, repeats the same mistakes, and spends your tokens doing it.

Cairn keeps that knowledge between sessions and between people, and hands it to whichever agent you open next.

How it works

Install once. Set up a repository in seconds. Keep working.

1

Install, and wire your agents once

uv tool install --python 3.12 cairn-brain cairn global install

Every agent on your machine gets Cairn’s tools and memory, at user level. Repositories without Cairn get a one-line offer to set it up, and nothing is written to them until you say yes.

2

Set up a repository

cd your-repo cairn init --no-deep

About fifteen seconds and no model needed: the code map, git history, specs and memories seeded from your docs and commits. Worktrees of the repository share its memory automatically.

3

Work as usual

# any agent, any session cairn status # what it knows cairn ui # browse it

Each session opens with the panel above. Agents capture what they do, and the next session, in any tool, starts from there.

Agent-neutral

One memory, whichever agent you open.

Built-in memories belong to one tool. Teams mix tools and switch often; Cairn’s memory follows the repository, not the vendor.

Your data

Your code never leaves your machine.

What an agent reads and runs is the most sensitive thing it captures, and the least useful to share. Cairn keeps it local. What your team does share is small, readable and stored where you already keep your code.
