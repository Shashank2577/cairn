03 Across the lifecycle

Every stage reads from it. Every stage writes back.

People and agents trade work from spec to ship. Cairn is the memory both sides share, so each stage starts with what the last one learned and the next cycle starts ahead. Pick a stage to see the real output.

Shared
memory

  1. Specify. /cairn.specify and /cairn.clarify write the spec; lasting decisions become memory.
  2. Plan. /cairn.plan grounds the plan in context, impact and recall; /cairn.tasks checks impact for every file.
  3. Implement. The brief at session start, context on each prompt, impact and why before edits.
  4. Review. cairn review-context shows callers, tests and history; cairn drift runs until clean.
  5. Ship. Git hooks re-sync after the merge; cairn standup reads commits against requirements.
  6. Learn. Session summaries, timeline facts and recorded learnings start the next cycle.

What becomes possible

  • Agents check the history before repeating a reverted fix.
  • A new hire's agent knows the team's conventions on day one.
  • Reviews see callers, tests and past reverts next to the diff.
  • Switch or mix agents without losing what any of them learned.
  • Knowledge stays when people move on to other work.
  • Impact reaches sibling repositories named in system.yaml.

Privacy

Your code stays where it already lives.

Your laptop

Where it all starts

Session capture, the code map, memories and the token ledger, in the repository's .cairn/ folder. None of it leaves unless you connect a team server.

Your git host

Already your repository

Specs, ADRs and shared config travel with the code and get reviewed like code.

Your team server

Optional, self-hosted

Shared memories and pushed sessions, with private blocks removed and secrets masked, under each member's token.

A model provider

Optional, per call

Prompts for summaries and facts, only when a model is configured. Turn it off and everything above still works.

  • Private stays private. Text inside <private> tags is never stored. Values that look like keys or passwords are masked before anything is written.
  • Loopback only. The local server listens on 127.0.0.1. Anything wider needs team mode with sign-in.
  • Works offline. Search vectors are computed on your machine.

Cost

No model on day one. Your model when you want one.

  • Free to start. The map, impact, why, drift, recall and the session panel are computed from your repository.
  • Bring a model for more. An Anthropic or OpenAI-compatible key, a local endpoint, or your signed-in Claude Code plan. Each job goes to the cheapest tier that does it well.
  • Budgets you set. Timeline facts stop at 150,000 tokens per sync by default, or turn them off.
  • A ledger of every call, on your machine:

06 For partners and investors

Memory is splitting by vendor. Cairn keeps it with the team.

The case in three parts, for anyone deciding whether to build on Cairn, partner with us or back it.

Why now

Teams run several agents, and each remembers inside its own product.

Developers mix Claude Code, Codex, Cursor, Copilot and others, often in the same week. What the team knows ends up scattered by tool and by person.

Why Cairn

Agent-neutral, local-first, open, and the customer owns the data.

One memory for seven agents. It runs on the developer's machine under Apache-2.0 and keeps what it knows in the repository, the team's git and the team's own server.

The business

Open source first, then Team, then Enterprise.

Developers adopt the open-source release one repository at a time. Teams pay for the hosted view across repositories. Enterprises pay for self-hosting, SSO and SCIM, audit and data controls.
